## 2. Prerequisites

* .NET SDK 10.0 (the project targets `net10.0`).
* Windows, macOS or Linux. Nothing else: no database server, no service, no configuration file.
* The sibling `..\AIOrchestrator\AIOrchestrator.csproj` when you build inside the source tree; a
  standalone build restores `Graphene.AIOrchestrator` from NuGet instead (dual-reference pattern).
* Internet access for the first run (the archive is ~158 MB of zips). Later runs work offline.

## 3. Commands

Run everything from `C:\Users\andre\OneDrive\Sorgenti\LegalAssistantTool`.

| Task | Command |
|---|---|
| Build | `dotnet build -c Release` |
| Harness, everything | `dotnet run --project LegalAssistantTool.Tests -- all` |
| Harness, one scenario | `dotnet run --project LegalAssistantTool.Tests -- laws` |
| Benchmark | `dotnet run -c Release --project LegalAssistantTool.Benchmark -- ..\..\benchmark-results.md` |
| Benchmark with per-query detail | `... -- ..\..\benchmark-results.md diag` |
| Pack the plugin | `dotnet pack -c Release -o ..\nupkgs` |
| Publish (CI) | push a tag: `.github/workflows/plugin-release.yml` |

The pack produces `Graphene.LegalAssistantTool.<1.yy.MM.dd>.nupkg`. The version is
`$([System.DateTime]::Now.ToString("1.yy.MM.dd"))`, the same convention as the other tools in the
solution, so no manual bump is ever needed.

## 4. The harness

`LegalAssistantTool.Tests` is not a unit-test project: it drives the tool exactly as the agent does
and keeps every artefact on disk so you can read it.

```powershell
dotnet run --project LegalAssistantTool.Tests -- all          # sync + laws + opinion + verify
dotnet run --project LegalAssistantTool.Tests -- opinion --echo
```

| Scenario | What it does | Fails when |
|---|---|---|
| `sync` | `LegalArchive.SyncNow(force: false)`, prints counts and timings | the archive is not ready |
| `laws` | 7 `GetLaws` calls (furto, rapina, truffa, locazione, lavoro, danno, a nonsense topic) | an answer lacks articles, or the nonsense topic returns content |
| `opinion` | 5 `LegalOpinion` calls (furto with facts, locazione with an attachment, thin facts, empty facts, no attachment) | an opinion is missing, or a refusal is missing where expected |
| `verify` | re-reads every `.out\*.md` and checks each `Art. N` and `n. N/YYYY` against the archive | a citation cannot be found in the corpus |
| `all` | the four above, in order | any of them |

* `--echo` mirrors every `Log.LogStep` line to the console (prefixed `>>` for monitor steps).
* The data root is pinned to `<project>\.data`, so a harness run never touches the user's real
  archive in `%LOCALAPPDATA%`. Delete that folder to test a cold install.
* The rendered answers are written to `<project>\.out\*.md`. Read them: they are the product.

The harness exits `0` with `RESULT: all checks passed.` or `1` with the list of failures.

## 5. Reading a run in the log

`Log.LogStep` writes to `logs/<pid>.txt` under the application base directory (AIOrchestrator
convention) and to `Log.CurrentLogFile`. A healthy `LegalOpinion` call produces this sequence:

| # | Log line (abridged) | What it proves | What to check if it looks wrong |
|---|---|---|---|
| 1 | `LegalService.Opinion: jurisdiction=IT, branch=...` then `LegalOpinion: start (jurisdiction=IT, branch=Criminal, facts=N chars, suggestions=M)` | The method was entered with the right branch | Branch wrong -> the agent passed the wrong enum |
| 2 | `Archive sync start: ... leggi=... giuri=...` | Which commits are installed | `none` -> first run |
| 3 | `Commit probe ...: remote=... local=... changed=False` | Change detection worked | `failed (...)` -> offline, archive reused (correct) |
| 4 | `Downloaded leggi zip: N MB` / `Extracted leggi to ...` | The zip round-trip | absent on a warm run (correct) |
| 5 | `Archive rebuilt: articles=4251 judgments=23049 engine=sqlite-fts5-bm25` | Normalisation + index | counts near zero -> parsing broke, check the source layout |
| 6 | `Research topics (N): furto, ...` | Topic detection | empty -> the facts do not trigger any topic: extend the thesaurus |
| 7 | `Curated articles: N (624, 625, ...)` | The editorial norm set | `Curated article penale X not found in the archive` -> wrong article number |
| 8 | `Round 1 on sqlite-fts5-bm25: query='...' articles=N judgments=M` | Round 1 ran with the raw facts | `articles=0` -> tokenisation or index problem |
| 9 | `Round 2 ...` / `Round 3 ...` | Expansion and rubric rounds | A round with 0/0 on both is usually a query of only generic terms |
| 10 | `Judgment citation query returned N hits` | Citation pass | 0 -> no scheda cites the curated articles |
| 11 | `Cassation pass returned N hits` | Cassation quota has candidates | 0 -> the court filter matched nothing (check `court` values) |
| 12 | `Relevance floor (2 of 24 anchors): articles A->B, judgments C->D` | The floor removed the long tail | Drops everything -> anchors are too generic |
| 13 | `Curated article Art. 624 c.p. kept in the answer (the engine missed it).` | The recall guarantee fired | Frequent -> retrieval is missing the norm, investigate before celebrating |
| 14 | `No article anchors the question: N judgments dropped.` | The "no law, no case law" rule | Expected on nonsense topics, suspicious otherwise |
| 15 | `Research finalised: N articles, M judgments.` | What the opinion will cite | 0 articles -> the caller gets the deterministic refusal |
| 16 | `Web search '...': N results.` / `Web search unavailable ... Enrichment skipped.` | Internet pass | The second line is normal offline and must not be treated as an error |
| 17 | `Web page <url>: usefulness=7 ...` then `Web enrichment: N pages rated, M used.` | Rating and reliability filters | All discarded -> `MinUsefulness` or domain lists |
| 18 | `Draft: model produced 4/4 usable sections, 0 sentences removed.` | Drafting + audit | `0/4` -> model unavailable (still a valid opinion) |
| 19 | `Attachment report.docx: 42000 chars exceeds budget 10666, summarizing.` | Attachment budget | Happens with long PDFs; the note appears in §11 |
| 20 | `LegalOpinion: completed (N chars, model=True, articles=10, judgments=6, webUsed=1, removed=0)` | Final shape of the answer | `removed>0` is not a bug: the guard did its job, §12 reports it |

The most useful single check: **step 15 against the rendered §4/§5**. If the log says 10 articles
and the Markdown shows fewer, the problem is in `LegalMarkdown`, not in retrieval.

## 6. Recipes

### 6.1 Add a legal topic

`Legal/LegalThesaurus.cs`, in `Build()`:

```csharp
new()
{
    Id = "danneggiamento-informatico",          // kebab-case, stable
    Name = "Danneggiamento informatico",        // shown in the answer title
    Branch = CaseType.Criminal,                 // or null for both branches
    Triggers = ["virus", "accesso abusivo", "database", "server", "hacker"],
    Expand = ["danneggiamento", "sistema informatico", "accesso abusivo", "interruzione"],
    CriminalArticles = ["615-ter", "635-bis", "635-ter", "635-quater"],
    DefencePoints = ["provare l'assenza di accesso abusivo", "..."],
},
```

Rules:

* **Every article number must exist and be in force in the archive.** Wrong numbers are logged as
  `Curated article penale X not found in the archive` and silently skipped, so a typo degrades
  quality without any visible failure. Check against `raw\leggi\<commit>\data\penale\codice\`.
* Triggers are matched on normalised text: use the stems people actually write, not the code words
  (the code words belong in `Expand`).
* Add at least three `DefencePoints`: they become §10 "Azioni consigliate".
* Run the harness `laws` and check the new topic appears in the log and in the output.
* Add a gold query to the benchmark for the new topic if it is a realistic case.

### 6.2 Change a ranking constant

`Legal/LegalRetriever.cs` lines 104-120. Change **one** value, re-run the benchmark, compare MRR@10
*and* P@5, then run `laws` + `opinion` + `verify`. Record the experiment in
[RETRIEVAL.md §10](RETRIEVAL.md#10-what-was-tried-and-rejected), including the values that lost.

### 6.3 Change the index schema or the tokenizer

`Legal/LegalIndex.cs`. Any change to `CreateTableSql`, `RankExpression` or the text written into a
column **requires a `FormatVersion` bump** in `LegalArchive.cs`, otherwise existing installations
keep the old index forever. Then run the benchmark: BM25 weights are not a matter of taste, they are
measured.

### 6.4 Add a search engine

1. Implement `ILegalSearchEngine` (`Id` + `Search(query, caseType, limit, kind, court)`).
2. Register it in `LegalSearchEngines.Registry` in `LegalRetriever.cs`.
3. Add it to the benchmark runner so the comparison stays honest.
4. It must return `LegalHit` with scores normalised to `0..1`; the merging code rescales anyway, but
   a wild score range distorts the ranking.

### 6.5 Change the opinion structure

`Legal/LegalMarkdown.cs` → `RenderOpinion`. Section numbering is computed in place, so inserting a
section means renumbering the `AppendSection` calls. If the section must be drafted by the model,
add it to `OpinionSections` and to the prompt in `BuildDraftPrompt`, and give it a deterministic
twin in `DeterministicSections`.

### 6.6 Change the drafting prompt

`LegalOpinionEngine.BuildDraftPrompt`. Two invariants:

* the lists of articles and judgments passed to the model are **closed**; never add "and other
  relevant provisions", the model will invent them;
* the output must stay a JSON object matching `OpinionSections`, because `AskJson` fails soft and a
  malformed answer silently degrades to the deterministic draft.

### 6.7 Change the web policy

`Legal/LegalWebEnrichment.cs`: the constants at the top and the two domain lists. Remember that
nothing from the web may ever appear in §4 or §5 - those sections come from the archive only.

### 6.8 Add an attachment format

`Legal/LegalAttachments.cs`: add the extension to `TextExtensions`/`HtmlExtensions` or a new case in
the `switch`. Keep the failure behaviour: an unreadable file becomes a note, never an exception.

### 6.9 Wire the tool into the host

`AIOffice.csproj` has a `BuildToolPlugins` target that builds the tool and copies the plugin plus its
dependencies and native `e_sqlite3` into `Tools\LegalAssistantTool\`. If you rename the assembly or
the package, update the `_LegalAssistantToolPlugin`, `_LegalAssistantToolDeps` and
`_LegalAssistantToolNative` items together, and check `Legal\LegalNative.cs` still finds the native
library next to the plugin.

## 7. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `the local legal archive is being prepared` on every call | The first install is still running, or the wait budget is too short | Raise `LEGALASSISTANTTOOL_READY_SECONDS` (max 900); check the log for `Download of ... failed` |
| `Archive unavailable: the source repositories are not available locally` | No internet on a machine that has never synced | Connect once, or copy a warm data root into `%LOCALAPPDATA%\Graphene\LegalAssistantTool` |
| Answers contain no case law | No article anchored the question (step 14) or the floor removed everything | Check the topics and the anchors in the log; extend the thesaurus |
| `Curated article penale 648 not found in the archive` | Wrong article number | Fix the number in the thesaurus |
| Everything is `0/4 usable sections` | No LLM provider, or the budget was exhausted | Expected; the deterministic draft is still a valid opinion |
| `SQLite Error 1: no such module: fts5` | The wrong `e_sqlite3` was loaded (host-provided instead of the plugin's) | Check `LegalNative.EnsureSqlite()` resolved the file next to the plugin |
| The benchmark reports `0.000` everywhere | The corpus is empty (`.data` deleted mid-run) or the gold articles do not exist | Run `sync` first; the runner prints the dropped gold numbers |
| Build fails with `MSB4019` on a harness project | `obj`/`bin` junctions pointing at deleted temp folders | Recreate the target folders, or delete `obj`/`bin` and restore |
| `dotnet pack` fails on the licence | `LICENSE.md` missing or not packed | It is referenced by `PackageLicenseFile`; keep the file name |

## 8. Release checklist

1. `dotnet build -c Release` - zero warnings from this project.
2. `dotnet run --project LegalAssistantTool.Tests -- all` - `RESULT: all checks passed.`
3. `dotnet run -c Release --project LegalAssistantTool.Benchmark -- ..\..\benchmark-results.md` -
   the winner must still be the hybrid engine; commit the regenerated report.
4. Update `README.md` §3.2/§3.3 if the numbers moved.
5. Bump `FormatVersion` if the normalised data or the index changed.
6. `dotnet pack -c Release -o ..\nupkgs`.
7. Push; `plugin-release.yml` publishes the package and the plugin zip when a tag is pushed.

## 9. House rules

These are not style preferences: breaking them breaks the product.

* **Never invent a source.** Any code path that produces an `Art. N` or `n. N/YYYY` must take it
  from `LegalCorpus`/`LegalResearch`. New prose generators go through `LegalCitationGuard.Audit`.
* **Deterministic first.** Every feature must work with no LLM. The model improves wording only.
* **Fail soft on the network.** A network error is logged and skipped; it never becomes an exception
  in the agent's face.
* **No configuration file, no database server.** Paths come from `LegalStorage`; knobs are
  environment variables with defaults.
* **Log the decisions, not the noise.** One `Log.LogStep` per decision point (what was chosen, what
  was dropped and why), no per-document logging.
* **XML documentation on every public and internal member** - `GenerateDocumentationFile` is on and
  the host surfaces these descriptions to the agent.
* **Any change to normalised data or index shape needs a `FormatVersion` bump.**
* **Measure ranking changes.** The benchmark exists so that "it feels better" is never the argument.
